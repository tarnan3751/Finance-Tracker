# Build

The workspace, the flavors and entry points, the Android configuration, signing, R8 and
obfuscation. Code: the root `pubspec.yaml`, `app/android/`, `app/lib/core/config/`,
`app/lib/bootstrap.dart`, `app/lib/main_*.dart`.

## The workspace

The root `pubspec.yaml` is a pub workspace (`finance_tracker_workspace`) over `app`,
`server`, `packages/shared_models`, `packages/api_client` and `packages/contract_test`.
Each member declares `resolution: workspace`; there is one dependency resolution and one
`pubspec.lock`, at the root, committed. `flutter pub get` or `dart pub get` in any member
resolves the whole workspace. A dependency added to one member must be compatible with
every other: the server's `test` is held to the version Flutter's pinned `flutter_test`
allows.

| Member | Package | Kind |
|---|---|---|
| `app/` | `finance_tracker` | Flutter app |
| `server/` | `finance_tracker_server` | pure Dart (shelf) |
| `packages/shared_models/` | `shared_models` | pure Dart |
| `packages/api_client/` | `api_client` | pure Dart, generated from `api/openapi.yaml` (Phase 2) |
| `packages/contract_test/` | `contract_test` | pure Dart, validates bodies against `api/openapi.yaml` and checks its structure |

Every member has its own `analysis_options.yaml`: `flutter_lints` for the app,
`lints/recommended` for the others, then the same strict language block, the same
generated-file exclusions and the same extra rules. The app's file also excludes `build/**`
and `android/**`, because the Flutter tool's migrator writes them back on every
`flutter analyze` when they are missing. `.fvmrc` pins Flutter 3.47.8; `.editorconfig`
sets the whitespace rules.

## Flavors and entry points

There is no `app/lib/main.dart`, so a run without `-t` fails instead of starting the wrong
configuration. Each entry point builds an `AppConfig` and calls `bootstrap`.

| Flavor | Entry file | Application id | App name | Server URL | Banner |
|---|---|---|---|---|---|
| `dev` | `lib/main_dev.dart` | `dev.tarnan.financetracker` | Finance Tracker Dev | `FT_SERVER_URL`, default `http://10.0.2.2:8080` | `DEV` |
| `demo` | `lib/main_demo.dart` | `dev.tarnan.financetracker.demo` | Finance Tracker Demo | none | `DEMO` |
| `prod` | `lib/main_prod.dart` | `dev.tarnan.financetracker` | Finance Tracker | `FT_SERVER_URL`, no default; must be `https` | none |

- `FT_SERVER_URL` is a `--dart-define`. `bootstrap` throws a `StateError` before `runApp`
  when `prod` is given a URL whose scheme is not `https`.
- dev and prod share the id registered with Plaid; demo never touches Plaid and installs
  beside either.
- The banner is a full-width strip, 16 dp tall, on the theme's error-container color with
  the flavor's name centred in small capitals, drawn by `FlavorBanner`
  (`app/lib/core/widgets/flavor_banner.dart`) from `MaterialApp.router`'s `builder`. It is
  laid out between the status bar and the app, not over it: the app gets the height below
  the strip with no top inset, so the strip never covers an app bar action. When it is
  shown the debug banner is turned off, since it would cover the top-end app bar action.
- The Android flavor and the `-t` entry point must agree; a mismatch runs the wrong
  configuration under the wrong id. No flavor is named `release`, `debug` or `profile`:
  AGP refuses a flavor named like a build type.
- The launcher label is the `app_name` string each flavor sets with `resValue`; AGP 9
  disables `resValue` by default, so `buildFeatures.resValues` turns it on.
- `assets/demo/receipt.jpg`, the demo's synthetic receipt photo (`app-core.md`, **The
  image source**), is declared in `app/pubspec.yaml` with `flavors: [demo]`, so only the
  demo APK carries it.
- `assets/fonts/Roboto-Regular.ttf` and `Roboto-Bold.ttf` (Apache-2.0, `LICENSE.txt`
  beside them, the files Flutter's `material_fonts` ship) are declared for every flavor:
  the monthly report's PDF embeds them (`export.md`).

## Android

- **Template.** `app/android/` is the Kotlin DSL template that `flutter create` generates
  with Flutter 3.47.8 (`flutter_tools/lib/src/android/gradle_utils.dart` holds the
  constants): Gradle 9.3.1 (`gradle/wrapper/gradle-wrapper.properties`), AGP 9.1.0 and
  Kotlin 2.4.0 (`settings.gradle.kts`), JDK 17, NDK `flutter.ndkVersion` (28.2.13676358).
  `gradle.properties` keeps the template's `android.newDsl=false` and
  `android.builtInKotlin=false`. The Gradle wrapper scripts and jar, `local.properties` and
  `GeneratedPluginRegistrant.java` are generated by the Flutter tool and not committed.
- **SDK levels.** `minSdk = 26`, `compileSdk = 36`, `targetSdk = 36`, written as integers
  rather than the `flutter.*` properties so a Flutter upgrade cannot move them silently.
  26 covers the Plaid Android SDK (25+) and the biometric and secure-storage libraries
  (23+) with headroom.
- **Package.** Namespace and application id `dev.tarnan.financetracker`; `MainActivity` is
  `app/android/app/src/main/kotlin/dev/tarnan/financetracker/MainActivity.kt`.
- **Backup.** The `<application>` element sets `android:allowBackup="false"`,
  `android:fullBackupContent="false"` and
  `android:dataExtractionRules="@xml/data_extraction_rules"`, which excludes everything
  (`domain="root"`) from cloud backup and device transfer. A Keystore-bound database key
  cannot follow a system backup; the app's own encrypted backup (`backup.md`) is the only
  path.
- **Receipt photos.** `image_picker` (BSD-3, behind `core/platform/image_source.dart`)
  needs nothing in the app's manifest: the plugin's own manifest, merged at build time,
  declares its `FileProvider` (`io.flutter.plugins.imagepicker.ImagePickerFileProvider`,
  authority `${applicationId}.flutter.image_provider`, over the cache directory) beside
  the Plaid SDK's, and a disabled service that lets Play services install the backported
  photo picker. The app declares no `CAMERA` permission, and the plugin asks for it only
  when the manifest declares it, so the camera intent and the photo picker run with no
  permission at all. The photos are kept in the app's private `files/` directory, which
  the backup rules above exclude with everything else. `image_picker`'s transitive iOS
  implementation and macOS file selector are held in `app/pubspec.yaml` to releases at
  least two weeks old.
- **Bill reminders.** `flutter_local_notifications` (BSD-3, pinned exactly at 22.3.2 in
  `app/pubspec.yaml`, behind `core/platform/reminder_scheduler.dart`) schedules through
  `java.time`, so `app/build.gradle.kts` enables core library desugaring
  (`isCoreLibraryDesugaringEnabled = true` in `compileOptions`, and
  `coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.4")`, the forms the
  plugin's README gives, which AGP 9.1 with `android.newDsl=false` accepts). The main
  manifest declares `RECEIVE_BOOT_COMPLETED` itself (WorkManager's merged manifest also
  brings it, but the reminders do not lean on that) and, inside `<application>`, the
  plugin's two receivers, both `exported="false"`: `ScheduledNotificationReceiver`, which
  shows a reminder when its alarm fires, and `ScheduledNotificationBootReceiver`, on
  `BOOT_COMPLETED`, `MY_PACKAGE_REPLACED` and the two `QUICKBOOT_POWERON` actions, which
  schedules the pending reminders again from the plugin's own cache. The plugin's manifest
  merges `POST_NOTIFICATIONS` and `VIBRATE`; there is no exact-alarm permission
  (`SCHEDULE_EXACT_ALARM` is denied by default from Android 14, `USE_EXACT_ALARM` is for
  alarm and calendar apps), so reminders are inexact and may come up to about an hour
  late. The small icon is `res/drawable/ic_stat_bill.xml`, a one-colour vector, named
  from Dart only, so `res/raw/keep.xml` keeps `@drawable/ic_stat_*` from the release
  build's resource shrinking. The plugin's transitive Linux implementation brings `dbus`
  (MPL-2.0), which is not part of the Android build.
- **Export.** `pdf` (Apache-2.0, pure Dart, pinned exactly at 3.13.1: the report's bytes
  are pinned by a hash golden) draws the monthly report. `flutter_file_dialog` (BSD-3,
  pinned at 3.3.3) saves a file through the Storage Access Framework's "Save as" dialog,
  which needs no permission; `share_plus` (BSD-3, pinned at 13.3.1; it needs AGP 8.12.1,
  Gradle 8.13, Kotlin 2.2.0 and Flutter 3.38.1 or later) shares one. Both sit behind
  `core/platform/file_exporter.dart` and need nothing in the app's manifest: `share_plus`'s
  merged manifest declares its own `FileProvider` (authority
  `${applicationId}.flutter.share_provider`, over `cache/share_plus/`, where it copies a
  shared file until the next share) and a receiver for the chooser's result. `pdf`'s
  transitive `qr` and `image`'s `posix` are held in `app/pubspec.yaml` to releases at
  least two weeks old.
- **Network security.** `src/main/res/xml/network_security_config.xml` refuses cleartext
  and trusts system certificates; it applies to demo and prod.
  `src/dev/res/xml/network_security_config.xml` overrides it for dev only, adding cleartext
  to `10.0.2.2` and `localhost` for the development server. The main manifest grants
  `INTERNET` in every build type. Dart's own `HttpClient`, and therefore dio, does not
  consult the network security config: the file governs platform networking only
  (WebViews, the Plaid SDK), and prod's HTTPS-only rule is enforced in Dart, by
  `bootstrap`'s check today and by the API client from Phase 2.
- **Icon.** `res/mipmap-anydpi-v26/ic_launcher.xml` is a placeholder adaptive icon: the
  vector `drawable/ic_launcher_foreground.xml` on `@color/ic_launcher_background`, the same
  vector as the monochrome layer. There are no per-density PNGs; minSdk 26 reads the
  adaptive icon everywhere.

## Signing

The `release` signing config reads four environment variables; no `key.properties` exists.

| Variable | Meaning |
|---|---|
| `FT_RELEASE_KEYSTORE` | path to the keystore file |
| `FT_RELEASE_KEYSTORE_PASSWORD` | keystore password |
| `FT_RELEASE_KEY_ALIAS` | key alias |
| `FT_RELEASE_KEY_PASSWORD` | key password |

With `FT_RELEASE_KEYSTORE` unset or empty, the release build type signs with the debug key
and Gradle warns `FT_RELEASE_KEYSTORE is not set: the release build is signed with the debug
key.` (the Flutter tool shows Gradle warnings only with `-v`). That keeps the release-mode
smoke run working on any machine. Keystores are gitignored (`*.jks`, `*.keystore`).

## R8 and obfuscation

- The release build type sets `isMinifyEnabled` and `isShrinkResources`, with
  `proguard-android-optimize.txt` plus `app/android/app/proguard-rules.pro`. The keep
  rules cover `com.plaid.**` (the Plaid SDK behind `plaid_flutter`) and the no-argument
  constructor of every Room database: the Plaid SDK brings WorkManager, which creates its
  Room database by reflection at startup, and without the rule the release app crashes on
  launch (`NoSuchMethodException: WorkDatabase_Impl.<init>`). The app's own classes are
  not kept. `image_picker_android` needs no rule: its channel is Pigeon-generated code
  with no reflection, the registrant names its plugin class, and AAPT keeps the provider
  the manifest names. The encrypted database needs none: SQLite3 Multiple Ciphers is a native library
  reached over FFI, and R8 only touches Java and Kotlin code. `flutter_local_notifications` needs
  none: its model classes are `@Keep` and Gson 2.12 ships its own rules (the plugin's
  README, from v19); the notification icon is kept by `res/raw/keep.xml` (**Android**).
  R8 accepts rules for absent packages, so no `-dontwarn` is needed yet. R8's mapping lands in
  `app/build/app/outputs/mapping/<flavor>Release/mapping.txt`.
- Dart code is obfuscated by the Flutter tool: `--obfuscate --split-debug-info=build/symbols`
  writes `app.android-<abi>.symbols` to `app/build/symbols/` (gitignored); keep them to
  symbolize stack traces with `flutter symbolize`. gen_snapshot warns that the intermediate
  `libapp.so` carries DWARF; AGP's `strip<Variant>DebugSymbols` removes it before
  packaging, so the shipped library has no debug sections.

## Commands

Run from `app/`. APKs land in `app/build/app/outputs/flutter-apk/app-<flavor>-<type>.apk`.

```sh
flutter run --flavor demo -t lib/main_demo.dart
flutter run --flavor dev -t lib/main_dev.dart [--dart-define=FT_SERVER_URL=<url>]
flutter build apk --debug --flavor dev -t lib/main_dev.dart
flutter build apk --debug --flavor demo -t lib/main_demo.dart
flutter build apk --release --flavor prod -t lib/main_prod.dart \
  --obfuscate --split-debug-info=build/symbols [--dart-define=FT_SERVER_URL=https://<host>]
```

CI (`.github/workflows/ci.yml`) runs `tools/gates.sh` (when it fails, the images alchemist
writes for a failing golden, `app/test/**/failures/**`, are uploaded as `golden-failures`,
kept 14 days), then the demo debug build (uploaded
as `finance-tracker-demo-debug`, kept 14 days) and the prod release build with obfuscation
as the R8 canary, on Flutter from `.fvmrc`.
